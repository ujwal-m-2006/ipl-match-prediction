Why the pre-match model is near chance — and why that is the honest answer

The winner model was re-evaluated at six independent cut-off points, holding out from the last two seasons (144 matches) up to the last eight (541 matches). Every window returned an AUC between 0.50 and 0.55. That stability across 541 test matches rules out sampling noise.

No pre-match feature correlates with the result above |r| ≈ 0.09 — not recent form, not head-to-head, not home advantage, not the Playing XI's career batting average. The home side wins about 52% of IPL matches. T20 is a short, high-variance format.

Playing XI strength, era-aware scoring levels and mirrored training fixtures lifted the model from below chance to chance. They did not invent signal absent from the data. The chase model reaches 0.90 on the same pipeline — the difference is information, not technique.

How it is built

Every layer, from collection to serving.

Data collection

  • The official iplt20.com feeds are the primary source — the same JSON the website itself renders from, so no HTML scraping.
  • Cricsheet back-fills 2008–2018, the seasons the official feed does not index.
  • Rate-limited to one request every 0.6 s, with retries, backoff and on-disk caching.
  • Every match is validated; inconsistent records are rejected rather than stored.

Modelling

  • Six algorithms compared per task: Logistic Regression, Random Forest, Gradient Boosting, XGBoost, LightGBM, CatBoost.
  • Features are built by walking matches in date order, emitting each row before folding that match's result into the rolling state.
  • Selection on ROC-AUC (classification) and RMSE (regression), with calibration reported alongside.
  • Playoff qualification via Monte Carlo over the winner model.

Run the interactive dashboard

The nine-page dashboard runs live on Streamlit Community Cloud. This page is static — a Streamlit app needs a running Python process, so it cannot be hosted on GitHub Pages itself.

▶ Open the live dashboard

Or clone and run it locally — the repository ships a prebuilt database and trained models, so there is no ingest or training step:

git clone https://github.com/ujwal-m-2006/ipl-match-prediction.git
cd ipl-match-prediction
pip install -r requirements.txt
streamlit run streamlit_app.py

On Windows, double-click setup.bat once, then run.bat.
